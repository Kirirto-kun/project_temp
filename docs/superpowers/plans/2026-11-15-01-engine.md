# Holdline. План 1 из 4. Ядро переговоров, сценарии и расчёты

> **Стек обновлён 15 ноября 2026:** обязательный источник истины — [TECH_STACK.md](../../../TECH_STACK.md). Применять его вместе с этим планом: TypeScript, PostgreSQL, LiveAvatar LITE + ElevenLabs connector; без собственного LiveKit, Python worker, OpenAI Realtime, Redis и S3/R2 для аудио. MediaPipe/pitchfinder — поздние опциональные слои.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** создать проверяемый движок переговоров, в котором состояние, суммы и результат определяет код, а модели классифицируют реплики и помогают с объяснениями.

**Architecture:** чистое TypeScript-ядро, отдельные адаптеры моделей, общие схемы данных и неизменяемый журнал ходов. Сервер вызывает движок через согласованный интерфейс; интерфейс пользователя получает только публичное представление состояния.

**Tech Stack:** TypeScript, Zod, Vitest; LLM через внедряемый адаптер. Конкретные версии и модели фиксируются в общем базовом коммите после проверки доступности.

**Spec:** [исходный PLAN.md](../../../PLAN.md), особенно §1–4, §6–8, §10–14; [brandbook.html](../../../brandbook.html).

**Разработчик:** A. **Ветка:** `codex/holdline-engine`.

**Соседние планы:** [2 — сервер и интеграции](2026-11-15-02-platform.md), [3 — интерфейс и клиентский голос](2026-11-15-03-product.md), [4 — первый созвон с аватаром](2026-11-15-04-avatar-intake.md).

## Общие ограничения

- B2C, только веб; основной путь без регистрации и логина.
- «Для жюри весь путь 0→7 бесплатный». Платные расширения не блокируют знакомство с коучем, запасной квиз, обычную тренировку, разбор и переигровку.
- «Все цифры считает код». Модель не меняет предложения, потолок, результат или эффект хода.
- Закрытый набор из восьми `MoveType`; невалидная классификация → один повтор → `offtopic`.
- 30 размеченных реплик классификатора, тесты всех строк таблицы переходов.
- «Сессия ≤ 5 минут»; сервер принудительно завершает её независимо от браузера.
- Бренд Holdline, английский интерфейс и USD первой версии; PLAN.md и брендбук обновлены для первого созвона.
- Вводный разговор D собирает данные, но не меняет CoreState. Поза, акцент, паузы и самооценка волнения не влияют на trust/patience, денежный потолок или платный доступ.

## На что обратить внимание при ревью

1. Принятие без предложения и завершённая сессия не создают фиктивную сделку — задача A2.
2. Уступка не увеличивает итоговые потери повторно; отсутствие сделки не изображается нулевым доходом — A2/A5.
3. Аренда уменьшает выгодную пользователю сумму, зарплата увеличивает; месяц и год не смешиваются — A1/A2.
4. Число словами, несколько сумм и попытка изменить правила через реплику не обходят контракт — A3/A4.
5. Переигровка сохраняет исходную задачу, а недоступная голосовая метрика остаётся неизвестной — A5/A6.

## 3. Контракт между разработчиками

Этот раздел определяет `contractVersion:1`. A переносит определения в Zod-схемы и экспортирует TypeScript-типы для B/C/D. Общая граница ввода `intakeContractVersion:1` описана здесь и в плане D, внутренние состояния intake — у D. Формат HTTP/ошибки — план B.

### Деньги и сценарии

- Все поля `*Minor` — целое безопасное число центов USD; `$104,000` = `10_400_000`. Значения, NaN, Infinity, дробные центы и переполнение проверяются на границе.
- `period: 'year' | 'month' | 'one_time'`. Зарплатные конфиги используют `year`, аренда — `month`; умножение на 12 допустимо только для явно обозначенного годового эквивалента.
- `objective: 'maximize' | 'minimize'`. Повышение/оффер — maximize; аренда/счёт — minimize. Пользовательский сценарий обязан выбрать одно направление.
- `Archetype = 'budget_guard' | 'analyst' | 'relationship' | 'hardliner'`. Это предложенные четыре поведенческих архетипа, не отдельные движки.
- `QuizAnswers`: `kind`, `description`, `counterpartRole`, `conversationDate` (ISO-дата или null), `currentMinor`, `targetMinor`, `marketLowMinor`, `marketHighMinor`, `period`, `fear`, `avatarId`. Типы сценариев: `raise | offer | rent | bill | custom`.
- Добавления для первого звонка: `currency:'USD'`, `moneyBasis:'gross'|'net'|'unspecified'`, `inputMode:'personal'|'example'`, `rangeSource:'user_provided'|'practice_assumption'|'example'`, необязательные `userRole` и `sourceIntakeId`. Форма C задаёт те же поля; basis=unspecified показывается явно и не означает gross. ScenarioConfig/summary/Debrief сохраняют currency/period/basis/inputMode/rangeSource, но не выводы камеры.
- `ScenarioConfig`: `id`, `version`, `kind`, `currency: 'USD'`, `period`, `objective`, четыре суммы из квиза, `reservationAmountMinor`, `initialOfferMinor`, `concessionStepMinor`, `patience0`, `trust0`, `maxTurns`, `objections`, `persona`.
- `reservationAmountMinor` берётся детерминированно: `marketHighMinor` для maximize, `marketLowMinor` для minimize. Это допущение симуляции, не знание реального бюджета. Поля marketLow/High сохраняют исторические имена, но при rangeSource=practice_assumption UI называет их тренировочными границами. `initialOfferMinor=currentMinor`; для оффера current — исходный оффер, для счёта — предъявленная сумма.
- `persona`: `name`, `role`, `archetype`, `avatarId`, `voiceKey`. Секреты и провайдерские ID остаются у B; `voiceKey` — стабильный ключ серверного реестра. C владеет публичными карточками и изображениями с теми же `avatarId`.
- `Objection`: `id`, `text`, `clearedBy: MoveType[]`. Флаги закрытия принадлежат состоянию сессии, а не изменяемому общему конфигу.
- `Move`: `type` из исходных восьми значений, `amountMinor: number | null`, `hasReason: boolean`, `tone: 'neutral' | 'apologetic' | 'assertive' | 'aggressive'`, `raw`. `tone` объясняет реплику, но не вводит скрытых числовых эффектов сверх таблицы.

| Тип | Обязательные поля и смысл |

Начальный activeMode=text; смену режима подтверждает сервер, увеличивая version и transportEpoch и отзывая прежний voice binding. sourceTurnKey не является секретом: B/C согласуют его получение из реального протокола в H+2. `replayRootId=id` первой партии; у всех её повторов сохраняется исходный root, а replayOf указывает непосредственного предка.

### Голос и разбор

- `VoiceBaseline`: `id`, `durationMs`, `wpm`, `f0MeanHz`, `f0StdHz`, `pauseRatio`, `rms`, `fillersPerMin`, `quality: 'valid' | 'insufficient'`, `unavailableReasons`. Измерения допускают null; ноль не подменяет отсутствие данных.
- `AudioManifest`: `recordingId`, `sessionId:string|null`, `intakeId:string|null`, `purpose:'baseline'|'session'|'intake'`, `durationMs`, `mimeType`, `timebase:'recording_ms'`, `turns:{turnId,t0Ms,t1Ms}[]`, `samples:{tMs,rms,f0Hz:number|null}[]`. Discriminated schema: baseline — оба id=null и turns пустой; session — только sessionId; intake — только intakeId, turnId из committed intake transcript. Все интервалы используют локальный ноль записи. При reconnect новая запись получает новый recordingId и явную привязку к сегменту; таймлайны не склеиваются по wall clock.
- `TurnVoice`: `turnId`, `turn`, `wpm`, `pauseRatio`, `f0MeanHz`, `f0StdHz`, `pauseBeforeNumberMs`, `fillers`, `rmsDipAtNumber`, `tensionIndex`; числовые/булевы измерения nullable, плюс `unavailableReasons` и `relativeToBaseline: boolean`.
- `VoiceMetrics`: `status: 'pending' | 'ready' | 'unavailable' | 'failed'`, `baselineId`, `turns: TurnVoice[]`, `formulaVersion: 1`, `reason: string | null`.
- `DebriefRow`: `turnId`, `turn`, `move`, `note`, `offerDeltaMinor`, `userConcessionMinor`, `meterEffect`, `voice: TurnVoice | null`, `betterLine: string | null`. Денежные поля не выводятся из текста комментария.
- `Debrief`: `sessionId`, `replayRootId`, `scenarioId`, `scenarioVersion`, `currency`, `period`, `objective`, `outcome`, `reservationAmountMinor`, `agreedMinor`, `leftOnTableMinor`, `gainMinor`, `rows`, `voice`, `persuasionScore: {value: number, rationale: string, source: 'model'} | null`.
- `leftOnTableMinor` и `agreedMinor` равны null при отсутствии сделки. В UI это «No agreement», а не `$0 earned` или полная цена сценария как потери.

### Граница первого созвона

`src/contracts/intake.ts` содержит общие `MoneyAnswer` и `IntakeHandoff` из плана D §4, без зависимости от UI/connector. D импортирует их в собственные схемы профиля. `quizDraft` может быть неполным даже после подтверждения собранных данных: неизвестный рыночный диапазон и ещё не выбранный avatar остаются в missingFields. Подтверждение профиля не означает готовность сценария.

`validatePracticeDraft(draft)` возвращает `{ready,missingFields,errors}`; проверяет валюту, период, basis, диапазон, доступный kind и обязательные суммы/персонажа. `buildQuizAnswers(draft,avatarId)` повторно валидирует заполненный draft и либо возвращает QuizAnswers, либо типизированную ошибку. B вызывает его только после owner-bound загрузки подтверждённой версии из D; слова модели и присланный браузером флаг confirmed не заменяют проверку.

`normalizePracticeMoney(input:MoneyAnswer, targetPeriod)` выполняет только разрешённое преобразование month↔year внутри USD с проверкой переполнения/целых центов; возвращает `MoneyCandidate={value:MoneyAnswer,formula:string,requiresConfirmation:true}`. FX и gross↔net не вычисляются. Доли цента требуют явно выбранного округления и подтверждения. `applyMoneyPercent(input,percentBasisPoints)` также возвращает MoneyCandidate, используется для «на 15% больше» и принадлежит A. Все четыре суммы должны иметь сопоставимые период/basis; неизвестные не заполняются моделью. `FieldError={field:keyof QuizAnswers|'_form',code:string,message:string}`.

Чтобы неизвестный рынок не блокировал знакомство, `suggestPracticeRange(current,target,objective)` предлагает **только с отдельным подтверждением** диапазон между текущей и желаемой суммой: raise `[current,target]`, rent `[target,current]`, при корректном направлении цели. Возвращает lowMinor/highMinor, rangeSource=practice_assumption, объяснение и requiresConfirmation=true. Это учебные границы, не оценка рынка. Неизвестный market в исходном профиле остаётся неизвестным; пользователь выбирает эту альтернативу явно. Правка current/target отзывает подтверждение производного диапазона.

## 4. Правила расчёта и переходов

Для обеих сторон вводится `utility(x) = x` при maximize и `-x` при minimize. «Больше» далее означает больше utility, а не всегда больше долларов. Ядро не выходит за reservation в выгодную пользователю сторону и не ухудшает уже предложенную сумму без явно принятой пользователем уступки.

- Уступка собеседника: движение от текущего offer к запросу пользователя на шаг, ограниченное reservation и запросом. Полшага округляется вниз до цента.
- `leftOnTableMinor = max(0, utility(reservation) - utility(agreed))`. Суммы уступок из журнала к нему не прибавляются.
- `gainMinor = max(0, utility(agreed) - utility(initialOffer))`; при отсутствии сделки null. Это выигрыш в симуляции, который C может группировать для счётчика без копирования денежной логики.
- `offerDeltaMinor = utility(after.offer) - utility(before.offer)`: положительное значение означает улучшение и в аренде, и в зарплате.
- `userConcessionMinor = max(0, utility(previousUserAsk) - utility(newUserAsk))`; это объяснение поведения, не дополнительные итоговые потери.
- `getQuizPreview`: `gapMinor=max(0, utility(target)-utility(current))`; annualized равен gap для year, gap×12 для month и null для one_time. Подпись — разрыв относительно своей цели, не доказанная потеря.
- Пример зарплаты: reservation `$112,000`, accepted `$104,000` → `$8,000` за год, даже если журнал содержит уступку `$8,000`.
- Пример аренды: reservation `$1,800`, accepted `$2,000` → `$200/month`, годовой эквивалент `$2,400`; нельзя показать отрицательную потерю.

Порядок проверок: уже завершена → no-op; превышен maxTurns/серверный deadline → timeout; специфические правила хода; clamp метрик; patience ≤ 0 → walked_away с приоритетом над обычным ответом. `accept` без offer не завершает сделку. Повторный finish не меняет исход уже принятой сделки.

| Ход | Уточнение к исходной таблице |
|---|---|
| `state_number` с причиной | Trust +3; открытое возражение → object, иначе шаг к допустимому запросу |
| `state_number` без причины | Patience −2; первое открытое возражение либо hold, если все закрыты |
| Нереалистичная сумма | Если превышение reservation в сторону выгоды пользователя >15% от reservation, этот случай имеет приоритет: patience −5 и hold; диапазон объясняется словами |
| Запрос между reservation и порогом 15% | Не превышать reservation; с причиной применить обычную ветку state_number, без причины — обычное возражение |
| `justify` | Закрыть первое подходящее незакрытое возражение, trust +2 и шаг; повтор того же закрытого возражения → hold без повторного бонуса |
| `concede` | Сравнить с предыдущим запросом по utility. Если уступки фактически нет — hold. Accept только при достижимой сумме, не лучше для пользователя, чем offer+step и reservation |
| `ask_question` | Patience +1 и probe без числовой уступки |
| `hold_silence` | Только явное событие пользователя после object: patience −1, trust +1, полшага. Тишина отключённого микрофона не является ходом |
| `ultimatum` | Trust<40: patience −10, walk_away при получившемся patience<15, иначе hold. Trust≥40: шаг в пределах reservation |
| `accept` | Принять именно текущее предложение, не новую сумму из текста |
| `offtopic` | Patience −1, hold |
